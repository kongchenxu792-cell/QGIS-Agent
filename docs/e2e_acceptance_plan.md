# AIQGIS 实机端到端验收方案（E2E Acceptance Plan）

> 版本：v1.0（2026-08-17，Solo 定稿，CEO 批准）
> 触发场景：任何涉及「应用可交付」的验收——P2/P3 切片完成后、GPU/模型环境变更后、版本发布前。
> 教训来源：2026-08-17 晚 Marvis 仅验证 API/GPU 后宣称「端到端通过」，CEO 实机第一条指令即失败（4b thinking 空输出 → 3 次重试耗尽 → 「未知原因」）。**本方案强制真实进程 + 真实窗口 + 真实 LLM + 逐条证据**。

## 0. 硬性定义
- **端到端 = 双击桌面快捷方式启动真实应用 → 真实窗口 → 真实图层 → 真实 LLM 推理 → 逐条指令断言**。任何「只测 API」「只测模块」「offscreen 无窗口」都不算端到端。
- **判定：全部 PASS 才算通过**。禁止「部分通过/基本可用」表述；任何一条 FAIL（含 UI 出现「未知原因」）即整体 FAIL，须修复后全量重跑。
- 证据锚点：每条指令必须有 ①指令原文 ②UI 显示结果（截图或原文复制）③执行耗时 ④日志时间戳（temp/e2e_log_<ts>.txt）。缺证据 = 该条无效。

## 9. 手算基准（L1550）期望值口径约定（Solo 裁决 2026-08-17 固化）

**认知固化：所有 buffer 相关期望值一律用 n 边形近似口径计算（SEGMENTS=5 → 20 边形）**

- 背景：QGIS native:buffer 默认 SEGMENTS=5（每象限 5 段 → 整圆 20 段内接多边形），这是 GIS 标准行为（QGIS 桌面默认同款），非引擎 bug
- 公式：20 边形面积 A = n/2 * r² * sin(2π/n)，n=20, r=500 → 772542.49 m²（与引擎 covered_area 分毫不差）
- 手算基准场景（正方形 10000m×10000m，中心 1 点 radius 500m）：
  - coverage = 772542.5 / 1e8 = **0.7725%**
  - gap = 100 - 0.7725 = **99.2275%**
  - pop_coverage = **0.7725%**（面积均匀时）
- 容差：±0.01% 不变（Solo 否决放宽容差）
- 禁止：不得因对拍差异改动模板 buffer SEGMENTS（模板 JSON 属红线）
