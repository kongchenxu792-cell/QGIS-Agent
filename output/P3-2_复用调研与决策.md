## 一、背景

P3-2 需要为分析链增加 run 日志与回滚（重放）能力。动手前按 CEO 要求做复用调研：
QGIS 原生项目文件（.qgs/.qgz）能否直接作为存储？DVC / MLflow / W&B 等数据版本/实验追踪工具是否适配？
结论先行：**全部否决，零新依赖，复用标准原语（sha256/JSON/时间戳短码/扁平目录），原创确定性重放。**

## 二、逐项调研与决策

### 1. .qgs/.qgz（QGIS 原生项目文件）

**映射关系**（我们的 workspace manifest ↔ .qgs maplayer）：

| workspace.json（P3-1） | .qgs maplayer 对应项 |
| --- | --- |
| layers[].name | layername |
| layers[].source | datasource |
| layers[].crs | srs |
| layers[].style | renderer-v2（及 symbology） |

**为什么不用 .qgs 做存储**：
- 全量 UI 快照超集：.qgs 序列化整个 QgsProject（画布状态/标注/布局/插件引用），体积大、噪声多，业务模型只需 4 字段
- XML schema 跨版本易碎：QGIS 版本升级可能改变 XML 结构，解析/写入依赖 QGIS 内部 API，反模式
- 自定义字段需侵入：我们要存业务元数据（country/notes/run 记录）必须扩 QGIS 命名空间或伴随文件，产生双链路维护代价
- 业务模型与 UI 快照解耦：manifest 是业务事实（可 diff/可审计/可测试），.qgs 是 UI 快照（易变/不可控）

**将来可复用的衔接点**（不浪费 .qgs 的价值）：
- P3-3 支持导出 .qgs：project.write() 一行映射，用 manifest 反向重建 QgsProject 后导出
- 导入 .qgs：QgsProject.read() 反填，再映射回 manifest
- style 字段：用 QgsMapLayerStyle XML 字符串（QGIS 官方单图层样式序列化），可无损往返，正是"衔接点"的落点

### 2. DVC / MLflow / W&B

| 工具 | 否决理由（一行一结论） |
| --- | --- |
| DVC | 依赖 Git 仓库 + 远程存储，本场景严禁 git 写（Solo 独有提交权、工作区不允许 git 写操作） |
| MLflow | 需 server + SQLite + UI 服务端，违反零新依赖嵌入式约束，且面向 ML 实验追踪（metric/model registry）语义不符 |
| W&B | 云端 SaaS，需账号 + 网络，桌面离线场景直接不符 |
| 共性 | 面向 ML 训练实验（metric/model registry），与 GIS 分析链执行快照（源文件指纹 + 参数 + 结果摘要）语义不同，均为过重 |

### 3. 结论：哪些复用、哪些必须原创

**复用（标准实践，零新依赖）**：
- sha256 指纹（source_hashes，前 16 位）——源数据变更检测
- JSON 记录（扁平文件）——run 记录/workspace manifest
- 时间戳短码（run_id/workspace_id）——唯一 ID，无状态、可排序
- 扁平目录布局（workspaces/<id>/、runs/<run_id>.json）——无数据库、可人工检视

**必须原创**：
- 确定性重放（replay_run）：取 run 记录 params 重新 execute，同参同果由 PipelineExecutor 纯函数契约保证
- 软回滚 warning 策略：源数据变更 → 追加 warning + changed_sources（不阻断），重载源图层后重放
- 分析链单点挂钩（_record_analysis_run）：四链收尾统一落盘，最小侵入

## 三、run 记录结构说明（附录：完整 JSON 样例）

落盘路径：`user_data/workspaces/<id>/runs/<run_id>.json`；无工作区时落 `user_data/workspaces/_recent/`。
字段：run_id（时间戳短码+随机尾）/ template_id / params / status（ok|degraded|failed，消费 P2-1/P2-2 状态机）/
result 摘要（stats/feature_count/message）/ outputs（result.output_file 非空时收集）/
source_hashes（{源路径: sha256 前 16 位}）/ created_at。

**重放语义**（回滚 = 重载源文件后确定性重放）：
- replay_run 读记录 + 校验 source_hashes：全部一致 → {ok, template_id, params}
- 任一变更 → 追加 warning「源数据已变更，重放结果可能不同」+ changed_sources（不阻断，软回滚）
- 真实执行：QGIS 内存图层不会自动重读外部修改的文件，须重新加载源图层再按 params 重放（同参同果）

## 四、衔接点备忘（给 P3-3 及后续）

- P3-3 工作区切换 = save + open 复用；run 记录随工作区走，切换不丢
- P3-3 可加「导出 .qgs」能力（project.write 映射，见第二节衔接点）
- style 无损往返用 QgsMapLayerStyle XML 字符串，时机成熟再接 UI 面板
